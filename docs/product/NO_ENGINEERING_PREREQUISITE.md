# No Engineering Prerequisite

The default customer is not assumed to know GitHub, Git, repositories, branches, CI, deployment, frameworks, package managers, or software-engineering vocabulary.

Primary onboarding:
1. **Give me your software** — choose a project folder or upload a project package.
2. **Connect where your software lives** — optional provider connections discovered by the system.
3. **Start from an idea** — future natural-language creation flow.

"Paste a GitHub URL" is an advanced fast path, not the product premise. Missing Git/GitHub is a system concern, not a user error.

Default UI uses outcome language: "work not safely consolidated", "shared main version", "parallel or leftover work", "automatic checks", and "live version". Raw engineering vocabulary belongs under optional Engineering Details.

A Doctor report must never prescribe an engineering action to the default user. It may ask for product intent. Remediation is described as work the system can handle, not homework for the user.
